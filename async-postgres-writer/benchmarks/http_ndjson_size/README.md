# HTTP-загрузка смешанного JSONB с сохранением размера NDJSON

В PostgreSQL 17.11 сравнили запись через HTTP API приложения с выключенным триггером и с `ENABLE ALWAYS`, когда триггер сохраняет `ndjson_bytes`. Наблюдаемая скорость изменилась примерно на −5% при двух загрузках и +5% при четырёх, но CPU PostgreSQL вырос на 34–38% в обоих сценариях. При двух повторах на конфигурацию замер показывает цену вычисления размера, но не даёт оснований ожидать ускорения записи на четырёх потоках в эксплуатации.

Стенд: Docker Compose в Colima на Mac ARM64, 6 vCPU и около 8 ГиБ памяти, один воркер Uvicorn, пул из четырёх соединений и лимит роли PostgreSQL в четыре подключения. WAL-буфер — 64 МиБ; таблицы и TOAST журналируются, `fsync`, `full_page_writes` и `synchronous_commit` включены. В каждом прогоне шли 2 или 4 одновременных PUT по 5 ГиБ и 27 234 строки на запрос. В NDJSON чередовались поля около 1 КиБ и широкие поля по 256 или 768 КиБ; для полей использовали повторяемый набор высокоэнтропийных Base64-значений. Всего восемь замеренных групп: 24 PUT, 120 ГиБ. Порядок переключения триггера меняли между повторами; пробный запуск в сводку не вошёл.

Скорость считали по времени до последнего HTTP 201, после коммита. Подготовка таблиц, `CHECKPOINT`, штатный перезапуск и сверка данных не входили в замер. Для времени и скорости ниже приведены медиана и диапазон двух повторов; CPU — медиана секунд за всю группу.

Снимки PostgreSQL и API делали примерно раз в секунду: короткие всплески могли не попасть в измерение, а полная память контейнера PostgreSQL включает файловый кэш. Медиана попарного изменения скорости при включении триггера составила −4,95% для двух загрузок и +4,80% для четырёх; CPU PostgreSQL вырос на 37,69% и 34,43% соответственно. CPU API снизился примерно на 10% в обоих сценариях, а объём WAL изменился менее чем на 0,01%. Контейнерный CPU включает небольшой вклад сборщика показателей. Во втором раунде свободные блоки диска VM освобождали до запуска таймера; для проверки после перезапуска изменили план запроса SHA‑256, сохранив тот же набор проверок.

После штатного перезапуска PostgreSQL у всех 24 загрузок совпали квитанции, число и номера строк, а также сигнатура SHA‑256 упорядоченных полей `payload`. При включённом триггере размеры всех строк совпали с расчётом, при выключенном остались `NULL`. В отдельной пробе незавершённый JSON после 8 МиБ корректного префикса дал HTTP 400 и не оставил ни строк, ни квитанции; повтор с тем же ID вернул HTTP 201 в обоих режимах. Это проверка штатного перезапуска и отката транзакции, без имитации внезапной потери питания.

## Как повторить

Нужны локальный Docker через Unix-сокет, Compose 2.24.4 или новее,
Linux-контейнеры с cgroup v2,
`uv` и достаточно свободного места на хосте и на диске Docker.
Для 4 × 5 ГиБ проверка перед стартом требует не менее 36 ГиБ свободного
места с каждой стороны. Не запускайте два экземпляра одновременно на одном
Docker Engine. Скрипт очищает таблицы перед каждым прогоном и перезапускает только
выделенный Compose-проект `ovation-http-ndjson-size`; используйте его для
временных данных. На Docker VM может понадобиться вернуть освобождённые
блоки тестового диска между прогонами.

Из каталога `async-postgres-writer`:

```bash
export POSTGRES_PASSWORD="$(openssl rand -hex 24)"
export BENCHMARK_WRITER_PASSWORD="$(openssl rand -hex 24)"
export WRITER_API_TOKEN="$(openssl rand -hex 24)"

uv run --locked python benchmarks/http_ndjson_size/stack.py setup
```

Быстрая проверка вместо полного прогона: по 64 МиБ на загрузку в каждой группе.
Она проверяет HTTP-квитанции, записанные строки и размер после перезапуска.
`--require-overlap` нужен полному прогону: короткая проба может закончиться
между двумя замерами активных COPY.

```bash
(
set -e
for trigger in off on; do
  uv run --locked python benchmarks/http_ndjson_size/http_load.py \
    --streams 2 --trigger "$trigger" --size-bytes 67108864 \
    --output "/tmp/ndjson-size-smoke-$trigger.json"
done
)
```

Полная серия: ровно 5 ГиБ на каждый HTTP-запрос. Первые четыре прогона
покрывают все сценарии, следующие четыре повторяют их в обратном порядке.

```bash
(
set -e
results=$(mktemp -d)
while read -r trial streams trigger; do
  uv run --locked python benchmarks/http_ndjson_size/http_load.py \
    --streams "$streams" --trigger "$trigger" --require-overlap \
    --output "$results/r$trial-$streams-$trigger.json" </dev/null
done <<'CASES'
1 2 off
1 2 on
1 4 on
1 4 off
2 4 off
2 4 on
2 2 on
2 2 off
CASES
uv run --locked python benchmarks/http_ndjson_size/check_rollback.py "$results/rollback.json"
printf '%s\n' "$results"
)
```

После сохранения результатов удалите только этот временный проект и его том:

```bash
uv run --locked python benchmarks/http_ndjson_size/stack.py down
```
