## Context

FastAPI уже обслуживает четыре маршрута данных, но его текущий `/openapi.json`
не содержит тело PUT, схему авторизации и часть ответов. Поддержка OpenAPI
не требует изменений в обработке NDJSON или запросах PostgreSQL.

## Goals / Non-Goals

**Goals:** единый контракт для приложения, документации и отдельного клиента;
проверка его соответствия реальному HTTP-поведению.

**Non-Goals:** второй сервер, новая схема БД, единый новый формат ошибок,
возобновление прерванной выгрузки и изменение настроек производительности.

## Decisions

1. Единственный исходник — `openapi/stream-writer.v1.yaml` в
   `async-postgres-writer`. Включить его в wheel и образ. FastAPI публикует его
   JSON-представление на `/openapi.json`; Swagger UI использует этот же документ.
   Ручное дублирование YAML в Python и привязка клиента к именам функций FastAPI
   не нужны. Несовместимые изменения требуют новой версии публичного API.
2. Для `application/x-ndjson` описать поток байтов и правила строк, не объявляя
   тело JSON-массивом. Модель одной выходной записи можно использовать в
   описании и примерах, но она не является схемой всего тела. Представление
   потока в [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.1.html) само по себе
   не диктует буферизацию на стороне клиента.
3. Описать два взаимоисключающих формата страницы через `oneOf`. Нельзя передавать
   вместе `offset` и `after_row_number`; зависимость между query-параметрами
   закрепить в описании операции и HTTP-тесте. Числа строк и смещения — целые
   `int64` с явными границами. Произвольные числовые значения внутри `data`
   не ограничивать форматами `float`/`double`.
4. Сохранить текущие виды ошибок: `detail` строкой, `detail` массивом ошибок
   валидации и `error`/`message` с `upload_id` для ошибок хранилища на маршрутах
   загрузки. Описывать форму по конкретному коду и операции, а не вводить
   глобальный новый формат.
5. CI проверяет валидность YAML и соответствие фактических HTTP-ответов контракту.
   Для протокола потока отдельно проверяются разбиение UTF-8, заголовки, целые
   записи после склейки и освобождение соединения при раннем закрытии. Одного
   сравнения YAML с `/openapi.json` недостаточно: эти артефакты имеют один источник.

## Risks / Trade-offs

- Ошибка после заголовков не превращается в JSON-ответ: сервер прерывает поток,
  а клиент проверяет завершение HTTP и число строк по `X-Row-Count`.
- Граница 128 КиБ относится к порции, отправляемой приложением. Прокси может
  изменить границы, а одна строка может занимать несколько порций.
- Swagger UI и некоторые инструменты генерации могут буферизовать тело. Примеры
  для больших данных показывают потоковый доступ без загрузки тела целиком.

## Migration Plan

Опубликовать контракт вместе с новой сборкой существующего сервера. Порядок
развёртывания БД не меняется; откат сборки возвращает прежний `/openapi.json`.
