## Why

Существующий сервис принимает и отдаёт большие результаты через HTTP. Текущая
схема FastAPI не описывает тело PUT, Bearer token и все ответы. Нужен версионируемый
контракт, по которому можно писать и проверять клиент отдельно от сервера.

## What Changes

- Описать действующий HTTP API PostgreSQL в OpenAPI 3.1: приём NDJSON, квитанция,
  страницы и полная выгрузка.
- Зафиксировать идентификаторы операций, форматы страниц, заголовки, варианты
  ошибок и правила завершения потока. Публиковать этот же контракт как `/openapi.json`.
- Проверять соответствие API контракту на CI без изменения существующих маршрутов
  и форматов ответов.

## Capabilities

### New Capabilities

- `postgres-stream-openapi-server`: машиночитаемый контракт и проверка существующего HTTP API.

### Modified Capabilities

Нет. Правила записи и чтения из `postgres-stream-write` сохраняются.

## Impact

Изменения касаются `async-postgres-writer`, его документации, сборки и проверок CI.
Контракт будет входом для [отдельного API-клиента](../../../../async-postgres-client/openspec/changes/postgres-stream-openapi-client/proposal.md).
Второй сервер, новые маршруты данных и миграция PostgreSQL не требуются.
