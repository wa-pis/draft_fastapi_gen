## Context

Пользователь выбрал PostgreSQL и HTTP NDJSON. Надёжность важнее частичного прогресса:
результат становится доступен целиком после commit. Приложение должно работать отдельно
от существующих сервисов репозитория.

## Goals / Non-Goals

**Goals:** async-поток без полного буфера, bounded resources, атомарный результат,
идемпотентный повтор и восстановление после неизвестного исхода commit.

**Non-Goals:** произвольная SQL-схема, Kafka/Hadoop, пакетные commits и фоновая очередь.

## Decisions

1. FastAPI принимает PUT NDJSON; asyncpg передаёт async iterable в COPY. Размер пула
   ограничивает число загрузок, ожидание соединения имеет отдельный timeout.
2. Принимается только UTF-8 JSON object на строку. Пустые строки, дубликаты ключей,
   NaN/Infinity и неподдерживаемые JSONB значения отвергаются; финальный LF необязателен.
3. Фиксированная схема `stream_writer`: `uploads` хранит receipt, `rows` — UUID,
   номер строки и JSONB. Имена таблиц и SQL недоступны клиенту.
4. COPY и receipt выполняются одной транзакцией; ошибки, отмена и обрыв входа вызывают
   rollback. Ответ успеха возможен только после подтверждения commit.
5. Отправитель выбирает UUID заранее. Конкурирующие запросы одного UUID сериализуются.
   Подтверждённый UUID сравнивается с SHA-256 точных исходных байтов: совпадение повторяет
   receipt без вставки, отличие даёт конфликт. Повтор тоже читает полный поток.
6. GET receipt позволяет разрешить неизвестный исход commit. Автоматического повтора
   с новым UUID нет; незавершённый запрос может ещё работать после потери ответа.
7. Явный `init-db` создаёт схему в существующей базе; `serve` не выполняет DDL.
   API защищён общим Bearer token, liveness публичный, readiness с авторизацией.

## Risks / Trade-offs

- Одна транзакция на 1–5 ГиБ удерживает соединение и создаёт WAL; объём JSONB/индексов
  может превышать размер потока. Нужны приёмка и расчёт мощности целевой БД.
- Ошибка COPY оставляет невидимые данные до VACUUM; rollback не означает мгновенное
  освобождение диска. Политику обслуживания определяет владелец PostgreSQL.
- SHA-256 байтов намеренно различает семантически одинаковый JSON с другим форматированием.
- JSONB не заменяет предметную схему и имеет ограничения по числам и Unicode.
- Гарантии сохранности commit зависят от настроек PostgreSQL и хранения.
- Общий token подходит одному доверенному отправителю; при нескольких независимых
  клиентах потребуется отдельное решение авторизации.

## Deployment

Не создавать базу автоматически. Init выполнять отдельно; runtime запускать непривилегированным
пользователем. За TLS proxy отключить буферизацию тела, согласовать timeouts/лимиты.
Удалённую БД подключать с проверкой сертификата и имени. Compose с PostgreSQL 17 и томом
предназначен для локальной проверки, а не как production-конфигурация кластера.

## Validation Strategy

Unit/fault-тесты парсера, лимитов, авторизации и HTTP-контракта. Отдельная приёмка на
реальном PostgreSQL: commit, поздний rollback, повтор, конфликт, конкуренция и receipt
после потерянного ответа. Проверить wheel, контейнер и нагрузку независимо; отсутствие
этих проверок явно фиксировать в результате работы.
