## Why

Результат калькуляции может занимать 1–5 ГиБ. Нужен отдельный async-сервис, который
принимает поток по HTTP и надёжно записывает его в PostgreSQL без накопления всего тела
в памяти. Отправитель должен отличать подтверждённый результат от оборванной загрузки
и безопасно восстанавливаться после потерянного ответа.

## What Changes

- Добавить самостоятельное приложение `async-postgres-writer` с HTTP NDJSON и PostgreSQL COPY.
- Сохранять строки и receipt атомарно, с UUID загрузки и SHA-256 исходных байтов.
- Предоставить GET receipt и идемпотентный повтор с тем же UUID.
- Ограничить размер потока/строки, время и число соединений; защитить API Bearer token.
- Добавить явный init схемы, контейнер, локальный Compose, тесты и инструкцию.

## Capabilities

### New Capabilities

- `postgres-stream-write`: async HTTP-приём и атомарная запись NDJSON-потока в PostgreSQL.

### Modified Capabilities

Нет. Kafka worker и Hadoop writer не изменяются.

## Impact

Новый каталог, собственный lock-файл и зависимости. Нужны существующая база PostgreSQL,
DDL-права для init, runtime-права на таблицы, дисковый/WAL-запас и TLS при внешнем доступе.
JSONB служит временным контрактом до определения предметных схем результата.

## Non-goals

Kafka, Hadoop, преобразование DataFrame, произвольные таблицы, частичные commits,
изменение бизнес-схемы и управление жизненным циклом кластера PostgreSQL.
