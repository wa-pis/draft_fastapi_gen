## Why

Python-приложениям нужен готовый HTTP-клиент для загрузки и чтения больших результатов.
Обычный клиент, который вычитывает ответ целиком, непригоден для выгрузки миллионов строк.
При обрыве важно отличать неполный экспорт от готового результата, а потерю ответа на PUT —
от подтверждённого отказа записи.

## What Changes

- Добавить отдельный пакет `async-postgres-client` с асинхронным API и типами квитанции, страницы и строки.
- Поддержать потоковый PUT, получение квитанции, пагинацию `after_row_number` и `limit/offset`,
  потоковое чтение NDJSON с проверкой полноты.
- Сверять клиент с OpenAPI 3.1 из [серверного изменения](../../../../async-postgres-writer/openspec/changes/postgres-stream-openapi-server/proposal.md).

## Capabilities

### New Capabilities

- `postgres-stream-python-client`: асинхронный Python-клиент для HTTP API результатов.

### Modified Capabilities

Нет. API сервера и схема PostgreSQL этим изменением не меняются.

## Impact

Новый каталог `async-postgres-client/` на уровне репозитория, собственные зависимости
и сборка. Клиенту нужны URL и Bearer token; установка сервера и доступ к PostgreSQL
для него не требуются. Выпуск проверяется против серверного контракта.
