# Проверки прототипа

Дата: 2026-10-29. Локальная машина: macOS ARM64, Python 3.13, Arrow 23.0.1.

## Выполнено

- Unit/fault-тесты обоих режимов и адаптера DataFrame/Arrow/Python records: 67 passed.
- Ruff check/format и строгая валидация OpenSpec.
- Сборка wheel/sdist и установка wheel с зависимостями в чистое окружение.
- Локальная демонстрация настоящих Parquet-файлов, повтор с тем же receipt.
- Потерянный ответ HDFS commit и SQL rename, конкуренция HDFS commit, конфликты,
  повреждение manifest, отказ credentials и остановка фонового обновления.

## Локальная потоковая запись

Синтетические слабо сжимаемые данные, порции примерно 8 МиБ, ротация файлов по 16 МиБ.
Это проверка реализации writer на локальной файловой системе, не скорости HDFS или Trino.
`input_mib` обозначает объём синтетического payload, фактический Arrow/Parquet немного больше.

| Вход | Строк | Parquet-файлов | Parquet, байт | Время | Peak RSS | Максимальный локальный файл |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 ГиБ | 1 048 576 | 64 | 1 074 079 905 | 2,700 с | 116 899 840 байт | 16 783 110 байт |
| 5 ГиБ | 5 242 880 | 320 | 5 370 397 089 | 13,112 с | 118 980 608 байт | 16 783 110 байт |

Для обоих результатов отдельно проверяются SHA-256 файлов и число строк Parquet против manifest.
Эти замеры получены до установки необязательного pandas. Наличие pandas может увеличить
базовый RSS из-за автоматического импорта Arrow; это не замер памяти уже готового DataFrame.

## Контейнер и кластер

- Runtime-образ: собран, Python 3.13, Hadoop 3.4.2, Arrow 23.0.1, pandas 3.1.0.
- Read-only smoke test: пройден; UID 10001, read-only root, tmpfs с noexec;
  32 МиБ, 32 768 строк, 2 Parquet-файла, 0,642 с, peak RSS 176 840 704 байт.
- Настоящий MIT KDC + защищённый HDFS: пройден `make integration`.
  Получен TGT по keytab, DataFrame записан с явной схемой (3 строки),
  затем 16 МиБ/16 384 строки в 2 Parquet-файла. Проверены lookup, повтор, конфликт,
  запрет перезаписи commit-файла, работа с фоновым обновлением credentials и отказ без тикета.
  Стенд: MIT Kerberos 1.20.1, Hadoop 3.4.2, SASL, block tokens, HTTPS_ONLY,
  dfs.datanode.synconclose=true, одна реплика. Порты наружу не публикуются.
  Для Java явно указан krb5.conf; штатный log4j направляет журналы в stderr.
- Реальный Trino/Hive: не проверен; нет подключения к целевому кластеру.

## Что нельзя считать доказанным

- Скорость SQL-вставки 1–5 ГБ: SQL-путь пока только функциональный прототип с fake-тестами;
  его много маленьких INSERT могут создавать много файлов и иметь низкую производительность.
- Атомарный no-replace rename таблицы и чтение metadata comments в вашем Trino/Hive.
- Production HA, replica loss, отключение питания и параметры настоящего KDC.
- HDFS commit сам по себе не обеспечивает публикацию в Hive/Trino.
